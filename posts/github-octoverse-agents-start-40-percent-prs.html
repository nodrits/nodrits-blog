AI Now Starts 40% of All Code: GitHub's Octoverse Counts the Agent Takeover

November 2, 2026 · Nodrits Solutions · 4 min read

AI now starts 40% of all code — or at least, of all code changes. GitHub's Octoverse 2026 report, published on October 28, 2026, found that by September 2026 more than 40% of pull requests on the platform began with a coding agent's first draft, up from 17% in March. That is about 110 million agent-started pull requests in a single month, roughly six times March's volume.

What happened

Octoverse is GitHub's annual census of its platform, and the 2026 edition covers October 1, 2025 to September 30, 2026, counting public and private repositories. The headline numbers: 1.3 billion merged pull requests over the year, an average of 3.5 million a day; 34.3 billion commits; 17.9 billion pushes. Agent-started pull requests merged within two weeks 90% of the time, against about 86% for pull requests without detected agent involvement, and 87% of agent-started PRs changed multiple files, against 79% of the rest. GitHub is careful about its own counting: its agent signal is a floor, since not all agent use can be detected — so the real share of agent-started work is probably higher than 40%, not lower. Among Copilot users who selected a model themselves, 61% used more than one model across their sessions in September, up from 50% four months earlier, and no single model carried more than 25% of requests.

Why it matters

The number that should change how teams work is not 40% — it is what happens after the draft. Median pull-request size rose 122% year over year, according to DX's engineering report covering more than 500 organizations, and at organizations where at least 80% of code was AI-authored, the median wait for a first review was 82 minutes. In other words, writing the first draft stopped being the slow part; judging, testing and merging it became the bottleneck. GitHub's report also warns, by omission, against the obvious misreading: it counts pull requests an agent started, not lines of code, and it reports no measure of defects, security bugs or reverts in agent-started work. An agent-configuration file in a repository correlated with eight times as many commits — a comparison of different repositories, not proof that the agent caused the output.

What it means for you

For any team shipping software, the practical response is to manage the review queue, not the typing: keep pull requests small and reviewable, automate tests before you automate authorship, and track defects and reverts alongside merge speed — because a merge rate without a quality measure is a vanity metric. Train reviewers explicitly, because reading AI-generated code carefully is now a core skill, not a side task. And pick models per step rather than per project: the data says even committed Copilot users already do.

The Nodrits take

Writing code was the bottleneck. It isn't anymore. The developer's job is moving from producing the first draft to deciding what ships — and that judgement is now the scarce skill.
