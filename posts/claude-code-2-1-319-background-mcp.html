Claude Code 2.1.319: Long Jobs Run in the Background Now

November 9, 2026 · Nodrits Solutions · 3 min read

Your coding agent just stopped waiting. Anthropic released Claude Code 2.1.319 on November 6, 2026: when an MCP server runs a tool call as a task, Claude Code now moves it to the background right away and tells Claude the result when it finishes — instead of blocking the whole session on a job that might run for twenty minutes.

What happened

Claude Code 2.1.319, released November 6, 2026, changes how long MCP jobs behave. Until this week, in most Claude Code sessions, Claude called a long-running MCP tool and the session sat inside that call; a fallback moved a call to the background only once it had run for two minutes. Now the call moves to the background immediately, with Claude told the result when it finishes — and an environment variable, CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND, restores the old wait-inside-the-call behavior. MCP tasks also leave their feature-flag gating behind in this release, so Bedrock, Vertex, Foundry and LLM-gateway setups get them too. Second, a new setting, permissions.denyInsteadOfPrompting, denies any tool call that would normally stop and wait for a permission prompt, and lets the turn continue — built for terminal sessions, subagents and teammates running unattended, where nobody is there to click Allow. The release also adds a claude-api latency-optimize command and fixes several permission-check bypasses, including a crafted environment prefix in Bash and a sandbox escape during worktree creation, per the changelog summaries.

Why it matters

Overnight jobs, CI pipelines, multi-agent teams — that is increasingly how Claude Code is used. Background MCP tasks remove a real friction: one slow report export or build no longer freezes the whole session. The deny-instead-of-prompting setting is the more consequential change, because it makes the safe failure mode the automatic one: an unattended agent that hits something it was not pre-approved to do now skips it and keeps working, instead of either hanging forever or, worse, being run with prompts disabled entirely to avoid the hang. The coding-agent race is now about who fails safest at 3 a.m., not just who writes the best code.

What it means for you

Update to 2.1.319, then do two things. For any unattended or scheduled Claude Code runs, turn on permissions.denyInsteadOfPrompting and pre-approve exactly the tools those runs need — anything else gets denied and the run continues, which is the behavior you want at 3 a.m. And if you use MCP servers with long-running tools, test one task-type call and confirm it backgrounds and reports back; if a workflow genuinely needs the result inline, set the disable variable for that workflow only. Note the scope: MCP tasks work in the terminal CLI. The VS Code extension and the desktop app do not have them yet.

The Nodrits take

The best coding-agent feature is the one that removes waiting — and the one that fails safe at 3 a.m. Deny-and-continue beats prompt-and-hang every single time nobody is there to click Allow.
