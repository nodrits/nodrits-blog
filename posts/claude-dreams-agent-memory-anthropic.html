Claude Dreams Between Sessions — Anthropic's Agent Memory Breakthrough

November 8, 2026 · Nodrits Solutions · 4 min read

Claude now dreams between sessions — and it remembers you. Anthropic published “The components of agent memory” on November 6, 2026, showing how Claude re-reads its own logs while idle, corrects notes that turned out wrong, and builds linked wikis from what it learned.

What happened

Anthropic's engineering post by Lance Martin splits agent memory into four layers — raw transcripts at the bottom, notes, representations, and a small block of injected context at the top — and measures each one. Memory, as Anthropic defines it, is knowledge Claude gains from experience that it retains between sessions, saved as files it can read later. The centrepiece is dreaming: offline time, while the agent is idle, in which Claude re-reads transcripts, compares them with the notes it saved, corrects notes that do not match, merges duplicates, and sometimes rebuilds the notes into a linked wiki. Anthropic credits the idea of sleep-time compute to researchers at Letta and UC Berkeley. The headline test used about 350,000 internal files from Stainless, a company Anthropic acquired in May — roughly 420 million tokens of company documents. Claude built a wiki from that corpus over repeated dreaming sessions, then answered 25 questions from it: wiki-only performance rose from 13% to 48% of graded criteria as dreaming scaled from 2 to 128 sessions, and with both search and wiki available it rose from 54% to 61%, against 53% for search alone, saving about 20,000 tokens per question. On the CL-Bench 1.0 database task, memory lifted Claude Opus 5.5 from 0.655 to 0.838, Sonnet 5.5 from 0.644 to 0.833, Opus 4.7 from 0.383 to 0.700 and Sonnet 5 from 0.306 to 0.610. The most vivid test is Pokémon Red: Sonnet 3.7 wrote down almost everything — 413 memory files across 225 folders — and earned one badge; Fable 5 kept nine files plus one dashboard and earned four. Dreaming even corrected a wrong PokéCenter location by checking the note against the transcript; without the fix, Claude looped three times and never reached Cerulean City. This is research, not a product launch: the post describes research setups on Managed Agents and Claude Code's auto memory, and does not announce dreaming as a general feature.

Why it matters

Memory is the next frontier after models. An agent that remembers gets dramatically better at long-running work — the CL-Bench jump from 0.655 to 0.838 is the size of a model generation, delivered by memory alone. The Pokémon result is the deeper lesson: what you remember matters more than how much you remember. Nine well-chosen files beat 413 indiscriminate ones. But the research is unusually honest about the risks: dreaming costs compute, checking every memory continuously is not practical, and a wrong note injected into every new session can propagate its error into every future task. The always-loaded memory layer must stay small — Claude Code loads only the first 200 lines or 25 KB of its MEMORY.md as an index — and Anthropic suggests focusing dreaming on information likely to change, tuned by how often memories are accessed.

What it means for you

The agent that knows your project will beat the one that re-reads it every time. Expect memory to become a feature you manage, like a database — not a hidden trick. If you build agents, the design rule Anthropic offers is worth stealing: tell the agent what memory is for, but not how to use it. And if you use Claude Code, the MEMORY.md file in your project is already the mechanism — keep it short, keep it true, and treat it as the index to everything else.

The Nodrits take

The honest part of this research is the warning: dreaming costs compute, and a bad note can haunt every future session if nobody checks it.
