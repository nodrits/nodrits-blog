GitHub Ships Copilot Fusion: Stop Picking the Model, Start Specifying the Task

October 30, 2026 · Nodrits Solutions · 3 min read

Stop picking the AI model. GitHub made Copilot Fusion generally available on October 28, 2026, at its Universe conference in San Francisco — a system that decides, for each coding task, which models to use and how they should work together. Developers now choose only an effort level. The models sort themselves out.

What happened

Fusion combines GitHub's existing automatic model selection with the multi-model orchestration of Project HydraFusion, introduced as a research preview in September 2026. It is available on all Copilot plans in Visual Studio Code, the GitHub Copilot app, the Copilot command-line tool and JetBrains IDEs, with more clients coming. Instead of selecting a specific model, developers pick Copilot Fusion from the model picker and choose one of three effort levels: Standard for everyday tasks, High for harder work and deeper reasoning, and Max for the most demanding tasks. From there Fusion runs one of three execution patterns: Single, where one model completes the task; Cascade, where a cost-efficient model attempts it first and a quality check either accepts the result or escalates to a stronger model; and Critique, where one model drafts, another reviews, and the first revises. Enterprise administrators decide which models Fusion can draw from, can restrict models without disabling them for the wider team, and can make Fusion the default. GitHub Enterprise customers can now use every Copilot feature without a separate subscription, paying only for the AI credits they consume. For a limited period, paid Copilot subscribers get a 30% discount on model costs when using Fusion; GitHub has not published an end date. Preview users of the earlier auto and HydraFusion settings are moved to the matching Fusion effort level automatically. Alongside Fusion, GitHub released a Copilot app that runs agent work across multiple repositories, and published its annual Octoverse report: more than 40% of pull requests in September began as an agent's draft, up from 17% in March, and the platform now counts over 225 million developers, including 32 million in India.

Why it matters

The headline numbers are GitHub's own and should be read that way. GitHub says Fusion Max lands within two points of Claude Code running Opus 5.5 Max on the Artificial Analysis Coding Agent Index, at roughly half the API cost, half the tokens and about 40% less time per task; Microsoft CEO Satya Nadella went further on LinkedIn, per The Next Web, describing frontier-level quality at up to 77% lower cost. Those are vendor claims awaiting independent benchmarks — GitHub published cost, token and time figures only for the Max tier, leaving Standard and High without their own published comparison. But the mechanism is sound even if the numbers soften: most coding tasks do not need a frontier model, and the waste comes from developers defaulting to the expensive model “just in case” and forgetting to switch back — the exact pattern AT&T's Hari Pokhrel described, saying Fusion Standard has cut unnecessary spending across the company. The deeper shift is who arbitrates between models: Fusion makes GitHub the router, and the router, not the model, becomes the product.

What it means for you

Test it on your own code before trusting the chart. Pick one real task you would normally send to your favourite premium model, run it once on Fusion Standard and once on your usual model, and compare the result and the usage shown in your Copilot usage report. If the cheaper path holds up, make it the default for routine work and keep the premium model for the hard cases. If you manage a team, decide now which models Fusion is allowed to touch — and set effort levels per repository and task type the way you set CI budgets.

The Nodrits take

Specification becomes the skill. When the router handles model choice, your leverage moves to writing intent, constraints and acceptance criteria clearly — a vague task routed brilliantly still produces vague code.
